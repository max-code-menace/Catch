# Catch — contexte pour Claude

App mobile (Expo + Supabase) pour faire du sport et rencontrer des gens près de chez soi. Lancement local : **Bruxelles d'abord** (première ville testée, décidé le 16 novembre), puis ville par ville. Équipe d'une personne.

## À lire d'abord

- `docs/produit.md` : décisions produit, choix techniques, plan de construction
- `docs/design-system.md` : couleurs clair et sombre, typo, navigation, animations, vibrations
- `docs/ux-writing.md` : ton, règle du mot « catch », glossaire
- `docs/recherches.md` : résumé des recherches UX et de l'audit concurrents
- `design/laboratoire-ux/` : avant de construire ou de retoucher un écran, regarder le pattern correspondant et sa variante recommandée (page Synthèse dans `src/app.js`, fiches dans `src/mod1.js` à `mod7.js`). **Mais d'abord** la « Contre-expertise du laboratoire » dans `docs/produit.md` : le labo n'est pas à jour et plusieurs de ses recommandations sont rejetées
- `AGENTS.md` : règles Expo (ne pas se fier à sa mémoire, lire la doc de la version installée)

## Où est quoi

| Dossier | Contenu |
| --- | --- |
| racine (`src/`, `app.json`, `package.json`…) | **L'app** (Expo SDK 58, expo-router, TypeScript). Il n'y a qu'une seule app : l'ancien dossier `mobile/` a été supprimé |
| `docs/` | Décisions et règles |
| `design/` | **Design de référence** (direction « Chaleur ») : captures dans `apercus/`, pictos SVG dans `pictos/` |
| `design/laboratoire-ux/` | **Laboratoire UX, à garder et à consulter** : 40 patterns, une centaine de variantes jouables, une recommandation par pattern et une page Synthèse. C'est la réserve d'idées pour rendre l'app plus agréable. Sources dans `src/`, version publiée : https://claude.ai/artifact/XnGqqCVsjx5U1CSBRzKAHR. Les « 10 corrections d'audit » n'ont jamais été notées dans le dépôt (liste perdue avec une ancienne conversation) |
| `emails/` | Modèles d'e-mails de connexion (code à 6 chiffres, bienvenue) |
| `supabase/migrations/` | SQL appliqué à la base |

Les fichiers `design/canvas/*.dc.html` sont générés par `design/canvas/generer_design.py` : modifier le script, pas les fichiers générés.

## Structure de `src/`

- `app/_layout.tsx` : polices, thème, pile de navigation. `app/(onglets)/` : `creer`, `index` (Carte + Liste), `messages`, `profil`. Par-dessus : `session/[id]` (détail), `connexion`, `catchee/[id]`, `messages/[id]` (groupe d'une session), `prive/[id]` (message privé), `notifications` (réglages)
- `components/` : `carte-sessions` (react-native-maps : Apple Plans sur iPhone, Google Maps sur Android), `pastille-session`, `fiche-session`, `pastille-lieu`, `fiche-lieu`, `liste-sessions`, `bouton-catch`, `choix-lieu`, `choix-date-heure`, `choix-joueurs`, `ecran-secondaire`, `barre-haut`, `barre-navigation`… Les fichiers `.web.tsx` remplacent les cartes par un fond uni, pour vérifier dans un navigateur
- `constants/theme.ts` : palettes `clair` et `sombre`, polices, rayons, ressorts. `constants/carte.ts` : thème du fond de carte
- `lib/theme.tsx` : `useCouleurs()`, `useTheme()`, `useStyles(creerStyles)`. `lib/sessions.tsx` : sessions et Catchs partagés. `lib/compte.tsx` + `lib/supabase.ts` : connexion. `lib/messages.tsx` : conversations, non lus, lecture, envoi et écoute en direct. `lib/notifications.ts` + `components/gestion-notifications.tsx` : permission, jeton, réglages, réaction quand on touche une notification. `lib/haptics.ts` : seul endroit qui déclenche une vibration. `lib/lieux-sport.ts` : lieux de sport (table `lieux`)
- `donnees/` : pictos (générés par `scripts/generer_pictos.py`), sports, forme d'une session

Règles de code :
- Noms de fichiers, composants et variables en français.
- **Aucune couleur en dur dans un écran.** Chaque fichier déclare `const creerStyles = (c: Palette) => StyleSheet.create({…})` et chaque composant fait `const styles = useStyles(creerStyles)` ; pour une couleur hors styles, `const c = useCouleurs()`.
